# 0.3.19 — Active Drops refresh filtering

**Status:** implemented and built.
**Date:** 2026-11-24.

## Fix

The Active Drops tab refreshes its table from `/partial/blocks`. That fragment
previously returned every active block, so permanent drops reappeared in the
Active Drops tab every two seconds even though the initial render filtered them.

The fragment now applies the same filter as the tab render: only blocks with an
expiry are returned. Permanent blocks remain exclusively in the Permanent Drops
tab.

A web test creates one temporary and one permanent block, verifies the two tabs
diverge, and verifies `/partial/blocks` returns only the temporary block.
