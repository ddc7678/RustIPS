# 0.3.6 — release candidate

**Status:** release candidate; final pre-1.0 validation complete for the lab
scope.
**Spec:** `requirements.md` revision 8, §13.3/§14, TEST-39/40.
**Date:** 2026-11-21.

## Summary

0.3.6 is the release candidate. It adds no detector features; it hardens and
validates the release:

* a security review with three fixes (DB mode 0600, config-parent chmod bug,
  hardened systemd unit);
* a clean-VM first-run test: install and service ready in **9 seconds**, with a
  scripted replay producing **4 active nftables blocks**;
* an upgrade/rollback cycle on the lab VM preserving rules/detections/geo;
* a short soak with RSS ≈43 MiB, ~1.1% of one core, zero restarts/drops and a
  flat DB;
* published 0.3.6 coverage scorecard;
* a checksummed release artefact.

No new crates were added.

## What changed

### Security hardening

* The SQLite database is forced to mode 0600 (state directory remains 0700).
* `setup` no longer changes the mode of a pre-existing config parent when an
  override path is used; this was found during RC testing (it had turned
  `/tmp` from 1777 to 0755). Only a newly created parent is set to 0755. A
  regression test covers it.
* The systemd unit adds `UMask=0077`; `PrivateDevices`, kernel tunable/module/
  control-group/clock/hostname protection; `RestrictSUIDSGID`,
  `RestrictRealtime`, `RestrictNamespaces`, `LockPersonality`;
  `SystemCallArchitectures=native`; and a restricted address-family set
  (`AF_UNIX AF_INET AF_INET6 AF_NETLINK AF_PACKET`).
* `systemd-analyze security` improves from **6.5 MEDIUM** to **4.1 OK**.
* `docs/security-review.md` records the threat model, findings, accepted risks
  and verification commands.

### Validation tooling

* `scripts/lab/soak.sh`: samples memory/CPU/restarts, DB size, packet/drop
  counters, log state and alert queue; writes JSONL and enforces short-soak
  gates.
* `scripts/scorecard.sh` now publishes by the current Cargo version;
  `docs/coverage/0.3.6.{md,json}` is the RC scorecard.
* `scripts/release.sh` includes the current scorecard in `dist/`.
* `scripts/lab/first-run.sh` was executed against a clean Debian 13 VM.

### Documentation

* `docs/security-review.md`.
* `docs/soak/0.3.6.md` plus JSONL samples.
* `docs/coverage/0.3.6.md` / `.json`.
* `docs/runbook.md` already covers install/upgrade/recovery/failure handling;
  this release validates it.

## Security review

* `cargo audit`: **0 vulnerabilities**; one unmaintained warning, `chrono
  0.4.45` (RUSTSEC-2026-0543, no fixed upgrade). Accepted for timestamp/duration
  use.
* Web auth/session/CSRF/Host guard/CSP reviewed; no open high-severity code
  defect found.
* Accepted risks: no TLS (SSH tunnel), unsigned artefacts, root daemon with
  capability bounding, admin-controlled webhook/geo URLs (SSRF is an admin
  capability), `/readyz` public on a non-loopback bind.

## Known limitations and deferred work

1. No TLS listener; loopback + SSH tunnel is the documented deployment.
2. Artefacts are SHA-256 checksummed but not signed.
3. `chrono` is unmaintained (no fixed upgrade); revisit.
4. File-only log sources, rotation, dual-source dedupe and DET-23 file ingestion
   remain deferred.
5. The optional eBPF/XDP capture path remains deferred.
6. The soak is a short lab run, not the 30-day production soak required for
   1.0; add synthetic traffic, alert failures and a geo update to that run.
7. No third-party penetration test has been performed.

## 1.0 decision

The 0.3.6 RC meets the defined lab gates: 144 tests, 100% of the defined
coverage corpus, 28/28 lab acceptance checks, clean-VM install in 9 s with a
first block, upgrade/rollback preservation, 4.1 OK unit exposure and a passing
short soak. The Snort fork remains **not triggered**.

Promotion to 1.0 should wait for the §14.1 soak criteria: at least 30 days of
production operation, no data-plane crash, no unplanned block outage, <1%
capture drop, a completed restore test and a final TEST-37 scorecard on the
released build.
