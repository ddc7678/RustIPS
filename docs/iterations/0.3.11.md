# 0.3.11 — clickable IP history, country/ASN and permanent block

**Status:** implemented, post-RC UI release.
**Date:** 2026-11-21.

## Summary

Every source address shown in the UI is now a button. Clicking it opens a
server-rendered history dialog for that address with:

* country (ISO code) and ASN from the GeoIP/ASN indexes;
* total detections, blocks, log events and strikes;
* the latest detections, blocks, the strike record and related log events;
* allowlist / active-block status;
* a **Permanently block** action when the address is blockable.

## UI behaviour

`pages::ip_link()` renders:

```html
<button type="button" class="ip-link" data-ip="203.0.113.7">203.0.113.7</button>
```

The shell contains one global `<dialog id="ip-dialog">`. `app.js` delegates
clicks on `[data-ip]`, fetches `/api/ip?ip=…`, and inserts the returned fragment.
This also covers rows rendered dynamically by the 2-second live updates
(dashboard recent detections and top sources).

Places updated:

* Dashboard recent detections and top sources;
* Detections table;
* Logs source column;
* Active blocks;
* Block history;
* Strikes;
* Rule dry-run results.

The dynamic dashboard renderer builds the same button instead of plain text.

## API

Authenticated route:

```text
GET /api/ip?ip=203.0.113.7
```

It returns an HTML fragment, not a full page. Invalid or missing addresses get
HTTP 400. Unauthenticated requests are redirected to `/login` by the existing
session middleware.

Data is bounded to the latest 100 detections, 100 blocks and 100 log events;
totals are shown so an operator can see the full historical size.

New DB queries:

* `detections_for_src()` / `detection_count_for_src()`
* `blocks_for_src()` / `block_count_for_src()`
* `strike_for_src()`
* `log_events_for_src()` / `log_event_count_for_src()`

## Country and ASN

The handler performs a GeoIP lookup against the in-memory indexes:

* country is the two-letter ISO code from the country index;
* ASN is shown as `AS<number>`;
* if no indexes are loaded, the dialog says **GeoIP index not loaded**;
* if the indexes are loaded but the address is not found, it shows **unknown**.

No new external lookups or network calls are made.

## Permanent block

When the address is not allowlisted and is not already permanently blocked,
the dialog shows:

```text
[Permanently block]
```

It submits the existing `/blocks/add` form with:

* `src` = the address
* `minutes = 0` (permanent)
* a fixed reason
* the current CSRF token from the page

The existing block handler still rejects loopback/private/implicitly allowed
addresses and the existing audit/notice path applies. If a temporary active
block exists, the button remains available and makes it permanent. An allowlist
entry or an existing permanent block suppresses the button.

## Security

* The endpoint is behind the normal authenticated session middleware.
* All stored fields and the IP itself are HTML-escaped.
* The fragment contains no script; it is inserted into the existing document.
* The permanent-block form uses the same CSRF token and block validation as the
  rest of the UI.
* `fetch()` uses `credentials: same-origin`, `cache: no-store` and detects a
  redirect to the login page.

## Known limitations

1. The dialog shows the latest 100 rows per section, not unlimited history.
2. Country is the ISO code; country display names are not stored in the compact
   index.
3. Historical rows with the `0.0.0.0` sentinel are shown but cannot be blocked.
4. The dialog history query is a synchronous read on the UI thread; it is
   bounded and small, but very large histories still benefit from retention
   limits.
