# 0.3.16 — optional service firewall and DET-27

**Status:** implemented and built.
**Date:** 2026-11-23.

## Summary

RustIPS can now operate as an optional default-deny host firewall. The feature
is disabled by default and enabled by an administrator from `/firewall` with
the same single-button state toggle used by the detector catalog. Blocked-source
enforcement is unchanged whether the firewall is on or off.

## Behaviour

When enabled:

1. Existing blocked-source drop rules remain first.
2. Established/related connections and loopback are accepted.
3. IPv6 neighbour discovery/router advertisements and DHCPv4/DHCPv6 replies
   are accepted.
4. Allow rules are generated for listening TCP/UDP services discovered from
   `/proc/net`, pinned ports, and enabled honeypot ports.
5. The remaining inbound traffic is rate-limit logged with the prefix
   `rustips-fw-drop`, then dropped or rejected.

The new **DET-27 Firewall default-drop** detector is fed by those kernel log
lines. It is alert-only by default because the packet is already denied, and it
has a shipped disposition rule plus a schema-v11 data migration for existing
databases.

## UI and configuration

- `/firewall` shows the live state toggle, effective allow rules, discovered
  system services, honeypot ports, and editable firewall settings.
- Settings are stored in `settings.firewall.settings` and apply live:
  discovery on/off, refresh interval, pinned TCP/UDP ports, honeypot inclusion,
  drop logging, and drop-vs-reject.
- Honeypot ports remain detector parameters; changing them still requires a
  RustIPS restart, after which the firewall allow set includes them.
- `[firewall]` in `config.toml` supplies defaults and is overridden by the
  live UI copy.

## Safety

- Discovery failures never shrink the active allow set; the daemon keeps the
  last-good plan.
- At startup the firewall is not enabled until discovery succeeds.
- The mode is only written to nftables in `enforce` mode; `observe` shows the
  planned rules without changing the kernel.
- `rustips check` reports state, discovery health and the observe-mode warning.
- `docs/firewall.md` documents operation, recovery and known limits.

## Verification

- 159 library tests and 14 integration tests pass.
- `cargo clippy --all-targets -- -D warnings` and `cargo fmt --check` clean.
- Generated ruleset accepted and applied in an isolated Linux network
