# 0.3.13 — dashboard resource graphs

**Status:** implemented, post-RC UI release.
**Date:** 2026-11-22.

## Summary

The dashboard now monitors the RustIPS process and its database:

* CPU usage as a percentage of one core;
* resident memory (RSS) in MB;
* database storage in MB, including the main SQLite file and WAL/SHM sidecars.

Each has a one-hour sparkline on the dashboard. Clicking a graph
opens a 24-hour dialog with larger graphs, current values, peaks and the sampled
time range.

## Sampling

A sampler in the scheduler thread records a point every 30 seconds:

| Metric | Source |
|---|---|
| CPU % | `/proc/self/stat` utime+stime, divided by elapsed wall time and `_SC_CLK_TCK` |
| RSS MB | `/proc/self/status` `VmRSS` |
| DB MB | `rustips.db` size plus `-wal` and `-shm` |

The first sample has no previous CPU tick baseline and therefore reports 0%.
Samples older than 7 days are deleted on each insert.

New `system_samples` table (schema v10):

```sql
CREATE TABLE system_samples (
    ts_ms   INTEGER PRIMARY KEY,
    cpu_pct REAL NOT NULL,
    rss_mb  REAL NOT NULL,
    db_mb   REAL NOT NULL
);
```

New DB methods:

* `insert_system_sample()`
* `system_samples_since()`
* `prune_system_samples()`

## Dashboard

A new **RustIPS resources** panel sits below the top statistics:

* three cards: CPU, Memory, Database storage;
* each card shows the current value, a sparkline and the peak over the range;
* the cards are buttons that open the 24-hour dialog;
* `app.js` refreshes the compact panel every 30 seconds via
  `/api/system?hours=1&compact=1`.

The dashboard query reads only the last hour so the page stays light.

## 24-hour dialog

The shell contains `<dialog id="system-dialog">` alongside the IP dialog. It
loads:

```text
GET /api/system?hours=24
```

The fragment contains larger versions of the same three graphs plus the sampled
time range. Points are downsampled to at most 240 buckets for display. The
endpoint is authenticated and read-only.

## Rendering

Graphs are server-rendered inline SVG:

* a filled area polygon and a stroked polyline;
* `viewBox="0 0 100 100"` with `preserveAspectRatio="none"`;
* CSS classes provide the CPU/memory/DB colors (no inline styles, so the CSP
  remains `style-src 'self'`);
* values are scaled to a per-series maximum; CPU has a 10% floor so a very
  quiet process does not produce a misleading full-height line.

## Known limitations

1. CPU is process CPU time as a percentage of one core; it can exceed 100% on a
   multithreaded burst.
2. Memory is RSS, not the sum of all mapped memory.
3. DB storage includes WAL/SHM but not filesystem block overhead or backups.
4. History is sampled at 30 seconds and retained for 7 days; the 24-hour dialog
   is downsampled for drawing.
5. The first CPU sample is 0% until a second tick baseline exists.

## Upgrade notes

* `Cargo.toml` is now `0.3.13`. Schema v10 adds only `system_samples`.
* No configuration change.
* Rolling back to a pre-v10 binary requires restoring a DB backup.
