# 0.2.0 — web UI and PAM authentication

**Status:** implemented, pre-release (packet sensor + first UI; log ingestion,
GeoIP and rules still absent).
**Spec:** `requirements.md` revision 8.
**Date:** 2026-11-18.

## Summary

0.2.0 adds the first administrator interface. A synchronous HTTP server is
compiled into the same binary, binds `127.0.0.1:10707` by default, and
authenticates against the host's PAM stack through `/etc/pam.d/rustips`.
Authorisation is group membership in `rustips-admin`; there is exactly one
authority level. Sessions are in-memory, cookie-bound, CSRF-protected and
revalidated against PAM, with a root-only one-time break-glass token for PAM
outages.

Three packet detectors were added to the existing sensor: DET-08
connection-rate abuse, DET-09 connections to declared tarpit ports, and DET-10
an SSH connection-rate proxy. Capture health (kernel packets and drops) is now
visible live, and the dashboard polls `/api/summary` every two seconds.

No new crates were added. HTTP, HTML, sessions, PAM (`dlopen`), NSS group
lookups and the CSPRNG all use the standard library, `libc` and the existing
dependency set.

## What changed

### UI (embedded, loopback-first)

* Dashboard: packets, bytes and live throughput, detections and blocks per
  minute, active blocks, capture drops vs kernel-delivered packets, uptime,
  recent detections, top sources, top ports, and a health panel.
* Detections: filter by detector, 50-row pagination, JSON evidence, and a
  one-click 1-hour manual block.
* Active blocks: source, reason, detector, strike, start, remaining time and
  unblock; manual block form (0 minutes = permanent).
* Block history, strikes/repeat offenders, allowlist CRUD, settings and audit
  log.
* Settings: effective bind/port, runtime overrides, PAM service, admin group,
  session timeouts, users with access, detection thresholds, ladder, retention,
  and the `ssh -L` tunnel snippet.
* Dark/light theme, keyboard focus styles, tablet-width layout, and
  confirmation prompts for destructive actions.
* Tables refresh from small HTML fragments every 2 s; no full-page reload.

### Authentication and authorisation

* PAM through `/etc/pam.d/rustips`, loaded with `dlopen("libpam.so.0")`.
  `pam_authenticate` followed by `pam_acct_mgmt`; a PAM failure is a denial.
* The password never leaves the conversation callback: it is not logged,
  echoed, hashed or stored, and the buffer is zeroed after `pam_end`.
* Group check via the native NSS `getgrouplist`, after PAM succeeds. A valid
  password without `rustips-admin` is a distinct, audited denial.
* Break-glass: `sudo rustips auth breakglass [--minutes N]` writes a one-time
  0600 token in the state directory (default TTL 30 min, 1–1440 allowed),
  prints it once, and consumes it on successful login. Break-glass is checked
  before the password limiter so a PAM outage plus failed passwords cannot lock
  the recovery path out.
* Login limiter: 5 failures per username and per source in 10 minutes → 15
  minute lockout. Every attempt is audited with user, source and result.
* Session cookies are `HttpOnly`, `SameSite=Strict`, `Path=/`, with a 30-minute
  idle timeout, a 12-hour absolute timeout, and a fresh token on login.
  Sessions revalidate against PAM every 5 minutes and on every POST; a removed
  group membership ends the session on the next action.
* `rustips auth test --user NAME` exercises the same PAM service and group check
  without a browser and audits the result.

### HTTP layer and safety

* HTTP/1.1 parser with a 16 KB header cap, 8 KB body cap, 64-connection cap,
  read/write timeouts, and form-only POST bodies.
* Host-header allowlist (`localhost`, loopback literals, the bound literal);
  foreign names get `421 Misdirected Request`, which blocks DNS rebinding.
* CSRF token on every state-changing POST; a missing or stale token is `403`.
* Strict CSP (`default-src 'none'`, self-hosted CSS/JS only), no inline script
  or style, `X-Frame-Options: DENY`, `nosniff`, `no-referrer`.
* Every stored/request value is escaped; notices are a fixed allowlist.
* Unauthenticated pages redirect to `/login`; `/healthz` is public and minimal;
  `/metrics` is served only while the listener is on loopback.
* Bind precedence: CLI (`--web-bind`, `--web-port`) > `RUSTIPS_WEB_BIND` /
  `RUSTIPS_WEB_PORT` > database override > configuration file.
* A non-loopback bind needs the settings checkbox, logs a warning, and shows a
  persistent banner. A saved DB override that cannot bind at startup is
  deleted automatically and the file value is used (FR-186).

### Detection additions

| ID | Behaviour | Default |
|---|---|---|
| DET-08 | Connection-rate abuse: new connections per source in the shared window | 120 per window |
| DET-09 | One SYN to a configured tarpit/unused port | any configured port |
| DET-10 | SSH connection-rate brute-force proxy | 10 SSH connections/min |

DET-08 shares the 10-second window; DET-10 uses its own 60-second counter. The
tarpit list is empty by default, so DET-09 is opt-in. All three produce the same
`Detection` records, evidence, cooldown, strikes and ladder as DET-01…07.

### Operations

* `rustips run --no-web`, `--web-bind ADDR`, `--web-port PORT`.
* `rustips check` now reports the web binding, PAM service, group and whether
  PAM is usable, with warnings instead of hard failures for a missing PAM file.
* `rustips setup` next steps include the SSH tunnel, the
  `usermod -aG rustips-admin` command, the check/status commands and the
  break-glass command.
* systemd unit gains `MemoryMax=512M`.
* Capture threads sample AF_PACKET counters every 5 s and publish kernel
  packets and drops to the UI/metrics.
* Database helpers for paged detections, recent totals, top sources/ports,
  block/detection counts and full audit rows.

## Known issues and limitations

1. There is no PAM service or root access on the development workstation, so a
   real PAM password login and `setup --install-service` were **not** exercised
   here. The PAM code is compiled, loaded and unit-tested; the failure path is
   exercised end to end. The lab script's `--install` run should confirm a real
   login.
2. Rules and log views (FR-184g/j) are absent until the rules and log
   subsystems land.
3. Settings edits are limited to bind/port; detection thresholds, ladder and
   retention are displayed but not editable in the UI.
4. Block hit counts and free-text history search are not implemented.
5. No API bearer token (FR-189).
6. Non-loopback binding is protected by the Host guard and a warning banner,
   but there is no TLS listener. The documented deployment remains an SSH
   tunnel.
7. The web server is intentionally small: one request per connection, no
   keep-alive, no chunked bodies, no HTTP/2.
8. Break-glass sessions skip PAM revalidation by design; they use the same
   session timeouts and are clearly marked.
9. Observe mode still does not accrue strikes (unchanged from 0.1.0).

## Upgrade notes

* `Cargo.toml` is now `0.2.0`. Database schema is unchanged
  (`user_version = 1`).
* `[web]` is a new optional config section. Old config files parse unchanged
  and receive the defaults: enabled, `127.0.0.1:10707`, service `rustips`,
  group `rustips-admin`, 30/720/5 minute timeouts. Because the UI is enabled
  by default, an upgraded install starts a loopback listener after restart.
* Run `sudo rustips setup --install-service` to create the `rustips-admin`
  group and `/etc/pam.d/rustips` if absent. Existing PAM files and units are
  never overwritten. Add the administrator with
  `sudo usermod -aG rustips-admin <user>` and start a fresh login session.
* The shipped unit now includes `MemoryMax=512M`. `--install-service` will not
  replace an existing unit; update `/etc/systemd/system/rustips.service`
  manually if you want the cap, then `systemctl daemon-reload`.
* No migration is required for detections, blocks, strikes or allowlist.
