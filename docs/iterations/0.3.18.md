# 0.3.18 — Active versus Permanent Drops and split service tabs

**Status:** implemented and built.
**Date:** 2026-11-24.

## Summary

The Firewall page now separates expiring and permanent RustIPS drops, and
splits discovered services into external and internal views.

## Tabs

* **Active Drops** — temporary blocks with an expiry, plus the manual drop form.
* **Permanent Drops** — blocks with no expiry, removed only by an administrator.
* **Admin Drops** — unchanged.
* **External System Services** — services reachable beyond loopback. The toggle
  writes an explicit drop rule ahead of established connections and allows.
* **Internal System Services** — loopback-only services. They remain visible for
  inventory but are protected by the loopback rule and have no drop toggle.
* **Honeypot** — unchanged.

`/firewall?tab=services` remains accepted as an alias for the external side.

## Service table cleanup

The System Services tables no longer carry separate **Status** and **Mode**
columns. The allow/drop toggle is the mode. Newly discovered services are
highlighted in yellow until acknowledged or toggled, so the status column is no
longer needed. The “Mark all services as seen” action clears the highlight.

  service toggling/acknowledgement and honeypot port CRUD.
- 161 library tests and 14 integration tests pass.
