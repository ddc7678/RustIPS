# 0.3.5 — distribution and first run

**Status:** implemented, pre-release (single-binary install, recovery/first-run
tests and operations runbook; file-only log sources and eBPF/XDP remain later).
**Spec:** `requirements.md` revision 8, TEST-39/40, DM-12, FR-199/211/214/217–219.
**Date:** 2026-11-21.

## Summary

0.3.5 makes a clean install a single-binary operation and documents the
operator path:

* `rustips setup --install-service` now installs the running binary at
  `/usr/local/bin/rustips`, so the copied `/tmp` file is no longer needed by
  the unit;
* `rustips diagnose` dumps effective paths, privileges, interfaces, PAM,
  nftables, DB, rules, geo, alerts and recent audit;
* `/readyz` reports component readiness beside the minimal `/healthz`;
* `rustips config check` is an alias for `check`;
* first-run/recovery safety is covered by `tests/cli.rs`;
* `scripts/release.sh` builds the checksummed single binary;
* `scripts/lab/first-run.sh` automates TEST-39 on a clean host;
* `docs/runbook.md` covers install, upgrade, recovery, day-2 checks, failure
  handling and uninstall.

No new crates were added.

## What changed

### `setup --install-service`

`install_service` now:

1. copies the running executable to `/usr/local/bin/rustips` atomically with
   mode 0755 (a no-op when already running from that path);
2. writes the systemd unit with `ExecStart=/usr/local/bin/rustips run`;
3. creates `rustips-admin` if missing;
4. installs `/etc/pam.d/rustips` only if absent;
5. runs `systemctl daemon-reload`.

It still never enables enforce mode, starts capture, or overwrites an existing
PAM file/unit without `--force`. `--dry-run` lists the binary path and all
would-be files without writing anything.

The copy is covered by a unit test (`install_binary_copies_mode_and_is_idempotent`).

### First-run and recovery safety (TEST-40)

`tests/cli.rs` runs the real binary against throwaway config/state directories:

* setup creates config (0600), state and DB, and stays in observe mode;
* a second setup refuses to overwrite without `--force`;
* `--dry-run` writes nothing and previews the install;
* missing config with an existing DB enters recovery and refuses to start;
* `setup --recover` keeps the DB;
* `--fresh` requires `--force` and archives the old state under
  `state/backups/pre-fresh-*`;
* an invalid config is a hard error;
* `config check`/`diagnose` run.

The actual root-only `--install-service` path is exercised by
`scripts/lab/run-tests.sh --install` on the lab VM, including the installed
binary path and unit `ExecStart`.

### `diagnose` and readiness (FR-203/214)

`rustips diagnose` prints:

* version, config/state/DB paths, startup state, root status;
* mode, capture configuration and resolved interfaces;
* web bind, PAM service/group, PAM file/libpam state;
* nftables availability;
* DB bytes, active blocks, detections, log events, rule count/version;
* journal cursor/status, geo status, alert targets/queue;
* the last five audit rows.

`GET /readyz` (public, like `/healthz`) returns `ready` plus checks for
database, journal state, geo, nftables, PAM, alert queue and capture counters.
It is intended for monitoring/first-run verification; `/healthz` remains the
minimal liveness endpoint.

### Release and install tooling

* `scripts/release.sh` builds `dist/rustips-0.3.5-linux-<arch>` and its
  `.sha256`.
* `scripts/lab/first-run.sh user@host` refuses a host that already has
  `/etc/rustips/config.toml`, copies the binary to `/tmp`, runs
  `setup --install-service`, starts the service, waits for `/healthz`, runs
  `check`/`status`, and asserts the elapsed time is under 600 s.
* `docs/runbook.md` is the operator path: install, first-run checklist,
  upgrade by binary replacement, rollback, day-2 checks, journal/PAM/nftables/
  DB/disk failure handling, uninstall and release checklist.

## Known limitations

1. TEST-39 was not run end to end on a truly clean VM in this session; use
   `scripts/lab/first-run.sh` on a clean snapshot or host.
2. Release artefacts are checksummed but not signed.
3. The shipped unit still runs as root (with capability bounding) rather than a
   dedicated user; `NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome` and
   `PrivateTmp` are enabled.
4. File-only log sources and DET-23 file ingestion remain deferred.
5. The optional eBPF/XDP capture path remains deferred.
6. `diagnose` reads effective config and process state; it does not bundle
   journal/DB content.

## Upgrade notes

* `Cargo.toml` is now `0.3.5`. No schema change (v7).
* `setup --install-service` now installs `/usr/local/bin/rustips` and points the
  unit there. If you previously installed the binary elsewhere, run
  `sudo rustips setup --install-service` from the new binary (or use
  `scripts/deploy.sh upgrade`) and verify `ExecStart`.
* `rustips diagnose`, `rustips config check` and `/readyz` are new.
* `scripts/release.sh`, `scripts/lab/first-run.sh` and `docs/runbook.md` are new.
