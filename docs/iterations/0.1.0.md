# 0.1.0 — sensor core

**Status:** implemented, pre-release (no UI, no log ingestion, no GeoIP).
**Spec:** `requirements.md` revision 8.
**Date:** 2026-11-18.

## Summary

0.1.0 is the packet sensor and its disposition path. A single binary captures
traffic, decodes IPv4/IPv6, runs the seven 0.1 detectors, records evidence in
SQLite, applies the strike ladder, and enforces blocks through an
RustIPS-owned nftables table. It ships in observe mode by default, and the
CLI covers setup, validation, running, inspection, manual blocks, allowlisting,
export/import and flush.

## Performance baseline

Method: release build, pcap replay of a 500,000-packet benign capture
(`scripts/gen_bench_pcap.py`), single processing thread, fast replay, SQLite
enabled. Host: AMD Ryzen Threadripper 3960X; rustc 1.100.0.

| Metric | Value |
|---|---|
| Packets | 500,000 |
| CPU (user) | 0.34 s |
| Throughput | ≈ 1.47 M packets/s |
| Peak RSS | 94.6 MB (includes the 34 MB capture file held in memory) |
| Short-run RSS | 12.0 MB |
| Release binary | 4.4 MB |

Notes:

* Replay holds the capture in memory; live capture does not, so the live
  steady-state figure is closer to the short-run number plus the state table.
* The source table was forced through eviction (≈ 3.6 packets per distinct
  source, well above the 16,384-source cap), which is the worst case for
  memory rather than the common case.
* The 1 Gbps / 100k pps design point (Q15) has roughly an order of magnitude
  of headroom on this CPU. The live path adds socket syscalls, so the live
  baseline belongs in the lab runs.
* Wall-clock runs include up to 500 ms of scheduler join at shutdown; the CPU
  column is the meaningful number.

## Known issues and limitations

1. Observe mode does not accrue strikes. Switching to enforce starts the first
   real attacker at strike 1 rather than reflecting observed history.
2. Detection state is keyed by source with a fixed 10 s window per detector.
   A source that stays under every threshold forever is never blocked (by
   design).
3. Pcap replay reads the whole file into memory.
4. `status` prefers the mode recorded by the last daemon start and falls back
   to the config file when the daemon has never run.
5. Kernel drop counts are only logged when capture stops; there is no live
   counter yet.
6. The BPF filter accepts VLAN frames wholesale so tagged IPv4/IPv6 is not
   lost; the decoder then rejects non-IP payloads.
7. No UI, PAM, log ingestion, GeoIP or webhook in this release. `setup` says
   so instead of advertising a UI that does not exist.

## Upgrade notes

First release: no upgrade path to preserve. Database schema is `user_version =
1`; config is `config_version = 1`. Future config additions will use
`#[serde(default)]` sections so existing files keep parsing; incompatible
changes will bump `config_version` and be rejected with an explicit message.
