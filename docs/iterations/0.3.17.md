# 0.3.17 — tabbed firewall, admin drops and service controls

**Status:** implemented and built.
**Date:** 2026-11-24.

## Summary

The optional service firewall is now organised into four tabs and owns the
Active blocks page, administrator-defined drop rules, discovered-service
controls and the honeypot configuration.

## Tabs

* **Active Drops** — the old Active blocks page. Shows active RustIPS-generated
  drops and keeps manual block/unblock. `/blocks` redirects to this tab.
* **Admin Drops** — add, edit, enable/disable and delete rules with optional
  source CIDR/IP, destination CIDR/IP, protocol (`any`, `tcp`, `udp`, `icmp`,
  `icmp6`) and a single port. They run after the loopback guard and before
  established connections and generated service allows.
* **System Services** — every discovered listening service. Services default to
  allow. The toggle writes an explicit drop rule for that service and marks it
  acknowledged. A first-seen service is tagged **new** until acknowledged; a
  **Mark all services as seen** action clears the badges.
* **Honeypot** — the DET-26 enable/hits form (moved from Settings) plus
  add/edit/delete controls for individual honeypot ports. The firewall allow set
  follows port changes immediately; the packet engine still restarts to watch
  newly added ports.

Discovery refresh, pinned ports, honeypot inclusion, DET-27 logging, and
drop-vs-reject are in a separate **Firewall settings** card below the tabs.

## Data model

Schema v12 adds:

* `firewall_admin_rules` — source, destination, protocol, port, enabled,
  timestamps and actor.
* `firewall_services` — `(proto, port, addr)` service identity, first/last seen,
  drop toggle and acknowledgement state.

Service discovery upserts rows without clearing the administrator's drop or
acknowledgement state. Stale rows are pruned after 30 days.

## Behaviour

* Admin and service drops are emitted before `ct state established,related`,
  so they can cut existing sessions.
* Loopback is accepted first, preventing an admin rule from locking out the
  local web UI.
* Admin and service drops only apply while the service firewall is enabled in
  enforce mode.
* Honeypot port CRUD writes the existing validated detection override, so the
  firewall plan updates live; DET-26 restart semantics are unchanged.
