# 0.3.4 — coverage gate

**Status:** implemented; the defined TEST-37 corpus passes.
**Spec:** `requirements.md` revision 8, TEST-37 / G-08 / DM-11.
**Date:** 2026-11-21.

## Summary

0.3.4 is the coverage gate before distribution work. It:

* closes the last detector-catalog gap by adding **DET-23**, the log-side HTTP
  access-log scan;
* adds a **versioned attack/benign corpus and scorecard harness**
  (`tests/scorecard.rs`, `scripts/scorecard.sh`);
* publishes the per-detector result in `docs/coverage/0.3.4.md` and
  `docs/coverage/0.3.4.json`;
* records the **Snort fork decision**: the defined corpus is 100% covered with
  zero benign blocks, so the fork is not triggered.

No new crates were added.

## What changed

### DET-23 HTTP access-log scan

The journal parser now recognises common/combined HTTP access-log lines:

```
203.0.113.5 - bob [21/Nov/2026:00:00:00 +0000] "GET /admin?x=1 HTTP/1.1" 404 123 "-" "curl/8"
```

It extracts the source IP, user, method, path (query stripped) and status into
new `LogEvent` fields, with template `http.access` and parser `http`. The Logs
page gained an **HTTP** column.

`LogEngine` adds DET-23 with the same thresholds as packet DET-11:

* 20 unique paths in 30 s, or
* 15 404/403 responses in 30 s,
* per source, with the existing cooldown and bounded per-source maps.

Schema v7 adds `log_events.method`, `.path` and `.status`. Existing databases
migrate in place. A one-time rule ("HTTP access-log scan escalate", DET-23,
ladder) is added when no rule references DET-23; fresh installs include DET-23
in the shipped log-auth escalation rule.

`[logs.detection]` gains `http_scan_paths`, `http_scan_404` and
`http_scan_window_secs` (defaults 20/15/30).

**Remaining limitation:** this consumes access lines that reach the journal.
Services that write access logs only to files still need the deferred
file-source slice; DET-23 is not a substitute for file tailing.

### Coverage scorecard

`tests/scorecard.rs` is the versioned corpus and gate:

* attack cases for DET-01…17 and DET-20…25 (DET-19 is not a detector; DET-18 is
  internal);
* packet cases for scans, floods, tarpits, HTTP DET-11…15 and slow scan;
* log cases for DET-16/17/21/22/23/24/25;
* a benign corpus (normal HTTP, TCP, UDP, ICMP, SSH/PAM/sudo/cron logs and a
  200 access line);
* a per-detector PASS/MISS table and `target/scorecard.json`;
* assertions for zero benign alerts/blocks and 100% of the defined cases.

`scripts/scorecard.sh` runs it and copies the result to `docs/coverage/`.
DET-18 escalation (1h → 24h) is verified by
`src/daemon.rs::repeat_detection_escalates_the_ladder`; a second daemon test
asserts an allowlisted detection never blocks.

## Scorecard result

**Corpus 0.3.4:** 23/23 defined detectors detected, **100% coverage**, **0
benign alerts**, **0 benign blocks**; 19/19 block-producing detectors produced
a block in enforce mode, while the 4 alert-only detectors (DET-17/20/24/25)
stayed alert-only. DET-18 escalation passes. The published breakdown is
`docs/coverage/0.3.4.md`; the machine-readable result is
`docs/coverage/0.3.4.json`.

This is coverage **of the defined corpus**, not a general detection guarantee.
The corpus is deterministic and versioned; expand it when adding detectors or
changing thresholds.

## Snort fork decision

The §19 fork is gated on built-in coverage missing the 97% target. The defined
corpus is fully covered and produced no benign blocks, so:

* **Do not start the Snort fork.**
* Mainline RustIPS remains the detection engine.
* Revisit only if a future, expanded corpus drops below the gate.

Recorded here and in `CHANGELOG.md`.

## Known limitations

1. The scorecard corpus is synthetic and defined in `tests/scorecard.rs`; it is
   not a general guarantee or a third-party traffic replay.
2. DET-23 sees access logs only when they reach the journal. File-only
   nginx/apache access logs require the deferred file-source slice.
3. DET-02 counts destinations that are local addresses; a single-host sensor
   does not generally observe sweeps of third-party hosts.
4. The benign corpus is small and deterministic; grow it when adding detectors.
5. TEST-38 (30-day accelerated footprint run) is not automated; current binary
   and RSS numbers are recorded in the iteration docs.
6. File tailing, rotation, dual-source dedupe and the optional eBPF/XDP capture
   path remain deferred.
