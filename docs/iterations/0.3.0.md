# 0.3.0 — journald host-log ingestion and the first log detectors

**Status:** implemented, pre-release (journald slice; file sources, DET-23 and
GeoIP/rules remain later work).
**Spec:** `requirements.md` revision 8, §6.2.1–6.2.2.
**Date:** 2026-11-20.

## Summary

0.3.0 adds host logs as a first-class input. The daemon supervises
`journalctl -f -o json`, normalises each entry into one bounded `LogEvent`, and
derives detections DET-16/17/21/22/24/25. Log detections use the same
`record_detection` path as packet detections, so allowlist precedence, observe
mode, the strike ladder, audit and nftables enforcement are unchanged.

The work is deliberately sliced. This release completes the **journald** half
of 0.3.0: ingestion, cursor resume, parsers for SSH/PAM/sudo/systemd, the six
log detectors, the Logs view, schema v2, and `rustips logs test`. File tailing
(FR-319…335), DET-23 and the dedicated nginx/apache/mail/syslog/JSON-lines
parsers are the next slice.

No new crates were added. `journalctl` is used through a supervised pipe
(FR-301) instead of linking `libsystemd`.

## What changed

### Ingestion (FR-300…307, 311, 318)

* `src/logs/journal.rs`: supervised `journalctl -f -o json --no-pager` child.
  The reader runs on its own thread with its own SQLite connection, a capped
  line reader (1 MiB/line), a bounded channel and a backoff/retry loop.
* Every entry advances the cursor. The cursor is checkpointed after each event;
  a partial unique index on `log_events(cursor)` makes a crash replay a no-op.
* First start backfills `logs.backfill_secs` (default 900 s). An unresumable
  cursor is retried, then cleared with a `journal.gap` record and a backfill
  fallback. The UI shows the gap and the current health.
* Include/exclude lists filter units and identifiers. The daemon's own
  identifier (`rustips`) is excluded by default; systemd's messages about
  `rustips.service` remain visible so DET-24 still sees a stop.
* Global and per-parser rate limits (default 10,000/s and 2,000/s) drop excess
  with counters while still advancing the cursor, so a flood cannot stall the
  reader.
* `journalctl` failing to start or exiting marks ingestion `degraded` and
  retries; capture and enforcement are unaffected.
* ANSI escapes are disabled when stderr is not a terminal, so the daemon's own
  journal lines are clean.

### Parsers and event shape (FR-304, 305, 308, 310, 312)

`src/logs/parse.rs` defines the normalised `LogEvent` and a small linear-time
registry keyed by journal identifier:

| Parser | Matches | Templates |
|---|---|---|
| `pam` | `pam_unix(...)`, `pam_*` failure text | `pam.auth_failure`, `generic` |
| `sshd` | `sshd`, `sshd-session`, `sshd-auth` | `sshd.failed_password`, `sshd.invalid_user`, `sshd.accepted`, `sshd.other` |
| `sudo` | `sudo` | `sudo.command`, `sudo.denied`, `sudo.auth_failure`, `account.modification` |
| `systemd-logind` | session open/close | `logind.session` |
| `kernel` | `kernel`, `audit`, `auditd` | `kernel.log` |
| `cron` | `cron`, `crond`, `anacron` | `cron.job` |
| `system` | nftables/audit/journald/RustIPS changes, account tools | `system.security_change`, `account.modification` |
| `generic` | everything else | `generic` |

Derived fields: timestamp, origin, source, unit, identifier, priority, host,
pid, user, PAM service, source IP, action, outcome, template. Messages are
truncated to `max_message_bytes` (default 1 KiB), control characters are
neutralised, CRLF is normalised, literal `redact` patterns are replaced, and
`store_raw = false` keeps provenance but drops the message. No regex or shell
interpolation is used. `sshd-session` was added after lab logs showed Debian
13's OpenSSH 9.8 uses it for pre-auth lines.

### Detectors (DET-16/17/21/22/24/25)

`src/logs/detect.rs` keeps bounded per-source windows, per-detector cooldowns
and the same `Detection`/`Observation` shape as the packet engine.

| ID | Rule | Default | Disposition |
|---|---|---|---|
| DET-16 | SSH failures per source | 5 / 10 min | strike ladder |
| DET-17 | SSH success after failures from the same source | 1 | alert only |
| DET-21 | PAM failures per source, any non-`sshd` service | 5 / 10 min | strike ladder |
| DET-22 | sudo denial/wrong password per user+source | 3 / 10 min | strike ladder |
| DET-24 | Security-relevant system change | 1 | alert only |
| DET-25 | Account/privilege change | 1 | alert only |

DET-21 skips PAM failures whose service/identifier is `sshd` so DET-16 does not
double-strike. DET-17 clears the source's failure window after reporting.
Detections with no derivable source use `0.0.0.0` and never block. DET-17/24/25
are alert-only by design; DET-22 enters the ladder only when the event carries
a source address (local sudo lines do not, so they remain alerts).

Provenance is recorded on the detection (`evidence_log_id` plus metadata):
journal cursor, identifier, template, user, service, source, priority and a
bounded evidence line.

### Disposition (FR-309)

`src/daemon.rs` extracts the old inline packet disposition into
`record_detection`, shared by packet and log paths. Order: insert evidence,
allowlist/implicit check, no-source and alert-only checks, observe mode, then
strike bump and enforcement. This keeps log detections out of a side channel
and gives every detection the same audit behaviour.

### Storage (schema v2)

* `log_events`: bounded event rows, indexes on `ts_ms`, `(origin, ts_ms)`,
  `(source, ts_ms)`, and a partial unique index on `cursor`.
* `log_state`: key/value rows for `journal.cursor`, `journal.status` and
  `journal.gap`.
* `detections.evidence_log_id`: links a detection to its triggering event.
* `prune_logs(days, bytes, now)`: age prune, then oldest-first size prune.
* v1 databases migrate in place with `ALTER TABLE` and new tables.

### UI

* `/logs`: origin filter (`journal`/`file`, file reserved for the next slice),
  free-text search, pagination, and columns for time, origin, parser, template,
  unit/identifier, priority, user, source IP, message and resulting detection.
  Journal health and cursor-gap banner at the top.
* Navigation entry between Detections and Active blocks.
* Detection rows hide the manual "Block 1h" action for alert-only and
  no-source detections, and label them "alert only".
* The web test now seeds a log event and log detection and asserts the Logs page
  renders and escapes them.

### CLI and configuration

* `rustips logs test --since 10m [--limit N] [--json]`: parser dry run against
  the journal, no database writes.
* `rustips status` prints the stored log-event count and journal state.
* `[logs]`, `[logs.journal]` and `[logs.detection]` are optional config
  sections with strict unknown-key rejection, defaults and a TOML template in
  `rustips setup`.
* New counters: `log_events`, `log_dropped`, `log_parse_errors`; the stop audit
  and shutdown log include them.

## Known limitations

1. File sources, rotation handling, multi-line records and DET-23 are not
   implemented. `Origin::File` exists but nothing produces it yet.
2. Mail, nginx/apache, syslog and JSON-lines parsers are not implemented;
   those lines fall back to `generic`.
3. The Logs page filters by origin and free text only; priority/user/source/
   parser/time filters and per-file state arrive with file sources.
4. `[logs]` is file-driven; it is not editable in Settings.
5. FR-317 (log-flood detection) is not implemented; rate-limit drop counters
   are the current signal.
6. Detection cooldown state is in memory, so a restart can re-alert sooner than
   the cooldown suggests. Evidence and counts remain exact because of cursor
   dedupe.
7. DET-24 alerts on legitimate service restarts, including upgrades. It is
   alert-only and cooldown-limited, but expect noise after maintenance.
8. Journal continuity depends on `journalctl`; there is no `sd-journal` binding.

## Upgrade notes

* `Cargo.toml` is now `0.3.0`. Database schema is v2; a v1 database migrates in
  place on first start (`ALTER TABLE detections ADD COLUMN evidence_log_id`,
  `log_events`, `log_state`). Back up `/var/lib/rustips/rustips.db` first, as
  with any upgrade.
* `[logs]` is a new optional section. Old config files parse unchanged and
  receive the defaults: enabled, 15-minute first-start backfill, 1 KiB
  messages, 10,000/2,000 events per second, 7 days / 128 MiB, `store_raw = true`,
  `exclude_identifiers = ["rustips"]`.
* The shipped unit already has `SupplementaryGroups=systemd-journal`; no change
  is required for a systemd install. A foreground run as a normal user needs
  `systemd-journal` membership.
* `/logs` is a new page. Existing sessions keep working; the detection page now
  hides the block action for alert-only and no-source rows.
* No packet-detector defaults changed.
