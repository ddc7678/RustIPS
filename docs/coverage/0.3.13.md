## Corpus contents

Attack cases (synthetic, deterministic):

* packet scans/floods: DET-01 vertical, DET-02 horizontal, DET-03 FIN, DET-04
  ACK, DET-05 empty UDP, DET-06 ICMP sweep, DET-07 SYN flood, DET-08
  connection rate, DET-09 tarpit port, DET-10 SSH rate, DET-20 slow scan;
* HTTP: DET-11 unique paths, DET-12 `wp-login`, DET-13 401 login burst,
  DET-14 TRACE, DET-15 request flood;
* logs: DET-16 SSH failures, DET-17 success after failures, DET-21 non-sshd PAM
  burst and DET-23 access-log path scan. DET-22/24/25 were retired in 0.3.10.

Benign cases: normal HTTP 200 requests, normal TCP connections, five empty UDP
datagrams, one ICMP echo, five ACK-only packets, a successful SSH login, a
session, an allowed sudo command, a cron line and a 200 access log. None
produced an observation; therefore none could block.

## Bounds and caveats

* These are synthetic cases against the detector engines and the disposition
  path; they bound the claim to this corpus, not to arbitrary traffic.
* DET-23 currently consumes HTTP access lines that reach the journal. Access
  logs written only to files still need the deferred file-source slice.
* DET-02 operates on destinations recognised as local addresses; a single-host
  sensor does not generally see a sweep of third-party hosts.
* The benign corpus is intentionally small and deterministic; expand it when
  adding detectors or changing thresholds.
* Re-run the scorecard for every release and publish the updated JSON/Markdown.

## Release gate decision

With 100% of the defined corpus detected/blocked and zero benign blocks, the
0.3.13 coverage gate is **met for the defined corpus**. The §19 Snort fork is
therefore **not triggered**; mainline RustIPS remains the detection engine.
This decision is recorded in `docs/iterations/0.3.13.md` and `CHANGELOG.md`.
